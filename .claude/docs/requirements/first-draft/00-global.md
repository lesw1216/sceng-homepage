## 0. 작업 기본 조건

- 작업은 기존 브랜치에서 직접 수행하지 않고 **새로운 브랜치를 생성하여 진행한다.**
- 브랜치는 `main` 브랜치를 기준으로 분기한다.
- 작업 브랜치명은 다음과 같이 한다.

`refactor/detail-first`

- 이하의 모든 요구사항은 **현재 상태의 프로젝트 디자인 및 구현 상태를 기준**으로 한다.
- 별도의 변경 요구사항이 없는 기존 구성, 데이터, 문구, 디자인 요소 및 기능은 임의로 제거하거나 변경하지 않는다.
- 요구사항에 명시된 수정으로 인해 기존 기능이 동작하지 않게 되어서는 안 된다.

---

# 1. 공통 용어 정의

이하 요구사항에서 사용하는 용어는 다음과 같이 정의한다.

### 회사의 대표 선

`회사의 대표 선`은 회사의 CI 색상인 다음 두 색상을 사용한 수평선을 의미한다.

- 오렌지: `#ED512C`
- 네이비: `#242145`
- 구성 비율: **오렌지 : 네이비 = 2 : 1**

대표 선을 사용하는 모든 영역은 동일한 색상, 비율 및 디자인 규칙을 유지한다.

### 색상 명칭

이하 요구사항에서 별도의 색상 코드 없이 색상명을 사용하는 경우 다음을 의미한다.

- **오렌지** → `#ED512C`
- **네이비** → `#242145`

### 헤더의 네비게이션

이하 요구사항에서 `헤더의 네비게이션`은 **헤더 오른쪽에 위치한 메뉴 항목 전체**를 의미한다.

---

> **위의 정의와 기본 조건은 이하 모든 요구사항을 구현할 때 공통적으로 적용해야 하는 필수 규칙이다.**

# 2. 전역 요구사항

## 2.1 인터랙션

- 클릭 이벤트가 존재하는 버튼, 탭, 필터, 페이지네이션, 로고, 프로젝트 카드 등 **사용자가 클릭할 수 있는 모든 UI 요소**는 마우스 Hover 시 일반적인 클릭 가능 요소의 **손가락 포인터 커서(`cursor: pointer`)**가 표시되어야 한다.
- 클릭 가능한 요소임에도 기본 화살표 커서가 표시되지 않도록 한다.
- Hover 상태와 Active 상태가 존재하는 요소는 두 상태가 시각적으로 구분되어야 한다.

---

## 2.2 배경색

- 페이지 또는 섹션의 배경색으로 **네이비 또는 오렌지 색상을 사용하지 않는다.**
- 페이지의 전체적인 기본 배경색은 **흰색으로 통일한다.**
- 별도의 요구사항에서 옅은 회색 등의 배경을 명시한 개별 UI 요소를 제외하고, 대형 섹션 또는 페이지 영역의 배경은 흰색을 유지한다.

---

# 3. Typography 및 폰트 요구사항

홈페이지 전체에서 글꼴, 글씨 크기 및 굵기가 페이지나 컴포넌트마다 임의로 달라지지 않도록 **공통 Typography 규칙을 적용한다.**

## 3.1 기본 폰트

홈페이지 전체 기본 폰트는 **Pretendard Variable**을 사용한다.

- 한글, 영문 및 숫자 모두 기본적으로 Pretendard를 사용한다.
- 페이지별 또는 컴포넌트별로 다른 폰트를 임의로 지정하지 않는다.
- Variable Font를 사용하여 여러 개의 개별 Font Weight 파일을 불필요하게 관리하지 않는다.

폰트 파일은 프로젝트 내부에서 로컬로 관리한다.

권장 구조:

```text
src/
├── app/
│   ├── layout.tsx
│   └── globals.css
│
└── fonts/
    └── PretendardVariable.woff2
```

Next.js의 `next/font/local`을 사용하여 로컬 폰트를 불러오고, 현재 프로젝트에서 사용 중인 Tailwind CSS의 `font-sans` 기본 폰트로 Pretendard를 연결한다.

Tailwind CSS 버전에 맞는 방식으로 설정하되, 컴포넌트마다 개별 `font-family`를 지정하지 않는다.

---

## 3.2 기본 본문

기본 본문 Typography는 다음을 기준으로 한다.

- Font Size: `16px / 1rem`
- Font Weight: `400`
- Line Height: 약 `1.6`

Tailwind 기준으로는 다음과 같은 기본 Scale을 우선 사용한다.

- `text-sm` → 14px
- `text-base` → 16px
- `text-lg` → 18px
- `text-xl` → 20px
- `text-2xl` → 24px
- `text-3xl` → 30px
- `text-4xl` → 36px
- `text-5xl` → 48px

`text-[17px]`, `text-[19px]`, `text-[27px]`처럼 특별한 이유가 없는 임의의 글씨 크기 지정은 최소화한다.

---

## 3.3 Font Weight

기본적으로 다음 네 종류만 사용한다.

- `400 / font-normal` → 일반 본문 및 설명
- `500 / font-medium` → 메뉴, 버튼, 필터, 강조 정보
- `600 / font-semibold` → 카드 제목 및 소제목
- `700 / font-bold` → Hero, Section Title 및 주요 Heading

특별한 디자인 목적이 없는 한 `font-light`, `font-extrabold`, `font-black` 등을 임의로 추가하지 않는다.

---

## 3.4 글씨 크기 기준

Desktop 기준 기본 Typography Scale은 다음과 같이 구성한다.

| 용도              | 글씨 크기 |    굵기 |
| ----------------- | --------: | ------: |
| Hero 메인 제목    |   48~56px |     700 |
| Hero 설명         |   18~20px |     400 |
| 주요 Section 제목 |   32~40px |     700 |
| 소제목            |   20~24px | 600~700 |
| 카드 제목         |   18~20px |     600 |
| 일반 본문         |      16px |     400 |
| 부가 설명         |   14~15px |     400 |
| Navigation        |   15~16px | 500~600 |
| 버튼              |   15~16px | 500~600 |
| 필터              |   15~16px |     500 |
| Footer            |   13~14px |     400 |

---

## 3.5 반응형 Typography

- 모바일에서도 일반 본문의 기본 크기인 `16px`은 유지한다.
- 모바일에서는 Hero 및 Section Heading과 같은 큰 제목만 단계적으로 축소한다.
- 본문 가독성을 떨어뜨리기 위해 모바일에서 전체 글씨 크기를 일괄 축소하지 않는다.

권장 기준:

- Hero: Desktop `48~56px` → Mobile `34~40px`
- Section Title: Desktop `32~40px` → Mobile `26~32px`
- 본문: Desktop/Mobile 모두 기본 `16px`

---

## 3.6 Line Height

- 큰 Heading: `1.2 ~ 1.3`
- 일반 본문: 약 `1.6`
- Navigation 및 Button: `1.2 ~ 1.4`

본문의 여러 줄 텍스트는 가독성을 위해 충분한 행간을 확보한다.

---

## 3.7 Typography 일관성

- 동일한 계층의 제목은 페이지가 달라져도 동일한 크기와 굵기를 사용한다.
- 같은 수준의 Section Title 간 크기 차이를 임의로 만들지 않는다.
- 같은 종류의 카드 제목, 본문, 설명, 버튼, 필터의 Typography 역시 공통 규칙을 사용한다.
- 특별한 이유 없이 컴포넌트 내부에서 임의의 `font-size`, `font-weight`를 추가하지 않는다.
