## 원인 분석 (재현 → 가설 → 검증)

`SiteHeader`는 `RootLayout`에 상주하므로 App Router의 client-side navigation에서
**언마운트되지 않는다.** 그런데 스크롤 스파이 `useEffect`의 의존성 배열이 `[]`였다.

결과:
1. 홈(`/`)에서는 정상 동작
2. `/achievements/[slug]`로 이동 → 효과가 다시 실행되지 않아 observer가
   **DOM에서 떨어져 나간 옛 섹션 노드**를 계속 관찰 → 모든 항목이 non-intersecting →
   활성 항목 사라짐
3. 메인으로 복귀 → 여전히 효과 미실행 → 새로 마운트된 섹션 노드에 observer가 붙지 않음
   → **전체 새로고침 전까지 활성화가 영구히 죽음**

문서의 두 버그 항목("상세에서 활성화가 풀림", "상세→메인 복귀 시 동작 안 함")과
"수정 오류"(활성화가 아예 작동하지 않음)가 모두 이 하나의 원인에서 나온다.

## 변경 파일

### `src/components/layout/SiteHeader.tsx`
- 스크롤 스파이 `useEffect` 의존성에 `pathname` 추가 (근본 원인 수정)
- 활성 항목을 파생값으로 계산
  ```
  activeId = pathname.startsWith("/achievements") ? "achievements"
           : pathname === "/"                     ? active
           : ""
  ```
  - 실적 상세에서는 실적현황을 활성으로 고정
  - 홈이 아닌 경로에서는 직전 홈의 활성 상태가 남지 않음
  - 효과 안에서 `setState`를 부르지 않으므로 `react-hooks/set-state-in-effect`
    (React Compiler 규칙) 위반 없음
- nav 색상 원복: 비활성 `text-navy` / 활성 `text-orange`
- 밑줄: 활성은 `bg-orange` 고정 노출, hover는 `bg-navy`가 좌→우로 확장
  (요구사항 Hover 절이 취소선 없이 "네이비 Underline"으로 남아 있어 그대로 따랐다)
- 모바일 메뉴도 동일한 navy/orange 규칙 적용
- 로고 높이 한 단계 축소: `h-10 sm:h-15`(40/60px) → `h-9 sm:h-12`(36/48px)

### `src/components/layout/navigation.ts`
- `ACHIEVEMENTS_SECTION_ID`, `ACHIEVEMENTS_PATH_PREFIX` 상수 추가 (매직 스트링 제거)

### 앵커 오프셋 정렬 (6개 파일)
`scroll-mt-24`(96px) → `scroll-mt-16 sm:scroll-mt-20`(64/80px)로 변경해
sticky 헤더 실제 높이(`h-16 sm:h-20`)와 정확히 일치시켰다.
- `HeroCarousel.tsx` `About.tsx` `TechSkills.tsx` `BusinessTabs.tsx`
  `Contact.tsx` `AchievementsBrowser.tsx`

### `.claude/rules/design-system.md`
- 헤더 nav 색 규칙을 navy/orange로 갱신 (사업영역 탭은 steel/navy 유지)
- 헤더 높이·로고 높이·`scroll-mt` 동기화 규칙 명문화

## 알려진 제약 · 주의사항

- **`00-bad-work.md`가 0 bytes(빈 파일)이다.** README 25행이 이 문서를 필수 참고 대상으로
  지정했지만 내용이 없어 참고할 수 없었다. 내용을 채워 주시면 반영하겠다.
- **client-side navigation 실제 동작은 브라우저에서 미검증이다.** 이 프로젝트에는
  headless browser 의존성이 없어, 원인 분석·코드 수정·SSR 마크업까지만 확인했다.
  `npm run dev`로 홈 → 실적 상세 → 홈 순서로 이동하며 nav 활성화를 확인해 주시기 바란다.
- **hover 밑줄 색이 navy, 활성 밑줄이 orange로 서로 다르다.** 요구사항 Hover 절이
  취소선 없이 남아 있어 문서대로 따랐다. 활성과 동일하게 orange로 통일할지 확인 필요.
- **문서에 `## 1.3`이 두 번 있다**("헤더 식별", "헤더 네비게이션 버그"). 뒤의 것은
  1.4로 보고 작업했다.
- 헤더 높이(`h-16 sm:h-20`) 자체는 이번에 바꾸지 않았다. 로고만 한 단계 줄였다.
- 실적 상세의 sticky 사이드바 `top-28`(112px)은 그대로 뒀다. 헤더(80px) 아래 32px
  여백으로 보이며 기능 문제는 없다. 헤더에 붙이려면 `top-24`로 조정하면 된다.
